# Swale API v1: frontend contract

- **Status:** DRAFT. The backend proposes it; the frontend reviews it.
- **Stable:** the endpoints marked **M1** become stable once agreed.
- **Provisional:** endpoints marked M2 and later. Their shapes may still change.
- **Changes:** go through the changelog at the bottom.

## 1. Basics

- **Base URL (dev):** `http://localhost:8000/api/v1`. The OpenAPI document is at `/api/v1/openapi.json`, and interactive docs are at `/docs`.
- **Format:** JSON. Map layers are **GeoJSON (RFC 7946)**:
  - `FeatureCollection` for lists, `Feature` for single items.
  - Coordinates are WGS84, in **`[longitude, latitude]` order**.
  - There's no `crs` member.
- **IDs:** opaque, stable strings such as `catch_basin:CB305116` or `incident:nyc311_69804630`. Use them as feature IDs for hover and selection state. Don't parse them, and URL-encode them in paths.
- **Times:** ISO-8601 in UTC with a `Z` suffix, e.g. `2026-07-22T18:36:00Z`. Converting to New York time for display is the frontend's job.
- **Units:** every field name carries its unit: `_in` (inches), `_ft`, `_in_hr`, `_min`, `_cfs`, `_ft3`. A number without a unit suffix is a count or a score.
- **CORS:** the dev origins are set with `SWALE_CORS_ORIGINS` on the backend. Tell the backend your dev-server URL, e.g. `http://localhost:5173`.
- **Versioning:** within v1, changes are additive only (new endpoints, new optional fields). Ignore fields you don't recognize. Breaking changes ship as `/api/v2`.

## 2. Trust fields: render these differently

Every feature has `properties.knowledge_type`:

| Value | Means | Suggested styling |
|---|---|---|
| `observed` | Measured or confirmed: a sensor reading, the DEP inventory, or a DEP field finding. | Solid |
| `reported` | An unverified public report, i.e. a 311 complaint. **It isn't proof** that the problem exists or still exists. | Hollow or outlined |
| `predicted` | Model output (a Swale simulation, DEP flood maps, an NWS forecast). **It isn't current flooding.** | Translucent or hatched, **always labeled with the scenario name and run time** |
| `inferred` | Derived by Swale's own rules, such as a risk score or an incident-to-basin link. | Dashed, labeled "inferred" |

Every feature also has `properties.source`:

```ts
interface SourceRef {
  id: string;             // a key in the data-source register, e.g. "nyc311"
  dataset?: string;       // the publisher's dataset ID, e.g. "erm2-nwe9"
  record_id: string;      // the original ID at the source
  url: string;            // a link to the original record
  updated_at?: string | null; // the source's own update time, when it gives one
}
```

Each list response's `meta.sources[]` gives a per-source `stale` flag. When it's `true`, grey the layer out and show "as of <fetched_at>". `stale` is measured from when the rows were fetched from the source, not from when they were loaded, so a replayed snapshot shows as stale once it's old.

## 3. Shared conventions

**Query parameters**
- `bbox=minLon,minLat,maxLon,maxLat` is **required** on every map-layer list endpoint.
  - It must be four finite numbers with min < max on both axes, and it must intersect NYC (−74.27, 40.49, −73.68, 40.92). Otherwise the API returns 422.
  - Send the visible map extent, never the whole city.
- `limit` defaults to 1,000, with a maximum of 5,000.
- `cursor` is an opaque value taken from `meta.next_cursor`.
- If `meta.truncated` is `true`, there are more features. Either page through them or zoom in.

**List response envelope:** a GeoJSON `FeatureCollection` plus a `meta` foreign member. RFC 7946 allows foreign members, and map libraries ignore them.

```ts
interface LayerResponse<P> {
  type: "FeatureCollection";
  features: Feature<P>[];
  meta: {
    api_version: "1.0";
    layer: string;                       // e.g. "catch_basins"
    request_bbox: [number, number, number, number];
    filters: Record<string, unknown>;    // effective filters, defaults included
    count: number;                       // features in this page
    limit: number;
    truncated: boolean;
    next_cursor: string | null;
    generated_at: string;
    sources: SourceFreshness[];
  };
}

interface SourceFreshness {
  id: string;
  dataset_updated_at: string | null;
  last_ingested_at: string | null;
  fetched_at: string | null;   // when the rows were fetched from the source; `stale` is measured from this
  stale: boolean;
}

interface Feature<P> {
  type: "Feature";
  id: string;
  geometry: GeoJSON.Geometry | null;     // null only on detail endpoints, when the source has no coordinates
  properties: P & {
    layer: string;
    knowledge_type: "observed" | "reported" | "predicted" | "inferred";
    source: SourceRef;
    ingested_at: string;
  };
}
```

**Errors** use RFC 9457 problem details, with `Content-Type: application/problem+json`:

```json
{
  "type": "/api/v1/problems/invalid-bbox",
  "title": "Invalid bbox",
  "status": 422,
  "detail": "bbox must be minLon,minLat,maxLon,maxLat with min < max on both axes.",
  "instance": "/api/v1/catch-basins?bbox=-73.97962,40.66457,-74.01995,40.69255",
  "errors": [{ "param": "bbox", "code": "inverted_lon", "message": "minLon must be less than maxLon" }]
}
```

Problem types:

| Type | Status |
|---|---|
| `invalid-bbox`, `bbox-outside-coverage`, `invalid-parameter` | 422 |
| `not-found` | 404 |
| `run-not-finished` | 409 |
| `upstream-unavailable` | 503 |
| `internal` | 500 |

## 4. M1 endpoints (first to ship)

In the examples below, source fields come from real records. Swale-generated values (`ingested_at`, `last_ingested_at`, `generated_at`, `build`) show the format only.

### `GET /health`

```json
{
  "status": "ok",
  "api_version": "1.0",
  "build": "<git sha>",
  "db": { "status": "ok", "engine": "surrealdb", "mode": "embedded" },
  "sources": [
    { "id": "nyc_catch_basins", "dataset_updated_at": "2025-12-18T16:29:33Z", "last_ingested_at": "2026-10-16T04:00:00Z", "stale": false }
  ]
}
```

`status` is `"ok"` or `"degraded"`. It's degraded when the DB is down or a source is stale. Even then, the endpoint returns 200, so the demo can show what's wrong.

### `GET /layers`

This lists every layer, including planned ones with `"available": false`, so the layer picker can be built now. The response is `{ "api_version": "1.0", "layers": LayerInfo[] }`.

```ts
interface LayerInfo {
  id: string;                    // "catch_basins" | "incidents" | ...
  title: string;
  knowledge_type: "observed" | "reported" | "predicted" | "inferred";
  geometry_type: "Point" | "Polygon" | "MultiPolygon";
  endpoint: string;              // e.g. "/api/v1/catch-basins"
  available: boolean;
  milestone: "M1" | "M2" | "M3" | "M4" | "M5";
  filters: string[];             // supported query parameters
  categories?: { id: string; label: string }[];
  attribution: string;           // e.g. "NYC DEP via NYC Open Data"
}
```

M1 layers:

| ID | Knowledge type | Available |
|---|---|---|
| `catch_basins` | observed | yes |
| `incidents` | reported | yes |
| `sensors` | observed | no (M2) |
| `flood_observations` | observed | no (M2) |
| `dep_flood_maps` | predicted | no (M2) |
| `simulation_results` | predicted | no (M2) |
| `risk_rankings` | inferred | no (M3) |

### `GET /sources`

This is the data-source register used for the "data as of" UI. The response is `{ "api_version": "1.0", "sources": [...] }`. Each entry has: `id`, `name`, `publisher`, `dataset`, `url`, `cadence`, `time_semantics`, `known_limitations[]`, `dataset_updated_at`, `last_ingested_at`, `fetched_at`, `stale`.

### `GET /catch-basins?bbox=…&limit=…&cursor=…`

```ts
interface CatchBasinProps {
  layer: "catch_basins";
  knowledge_type: "observed";          // the inventory record; says nothing about condition
  unitid: string;
  area_ids: string[];                  // e.g. ["BK0601"]
  state_plane: { x_ft: number; y_ft: number; crs: "EPSG:2263" } | null;

```

### `GET /catch-basins/{id}`

Returns a single `Feature` with the same properties, plus `links.incidents`, which equals `/api/v1/incidents?basin=<id>`.

### `GET /incidents?bbox=…&category=…&verification=…&since=…&until=…&basin=…&limit=…&cursor=…`

**Filters**

| Parameter | Accepts | Default |
|---|---|---|
| `category` | A comma-separated list | All categories |
| `verification` | A comma-separated list of statuses | All statuses |
| `since` / `until` | Filters on `reported_at` | `since` = 365 days ago, echoed back in `meta.filters` |
| `basin` | A basin ID; returns incidents linked to that basin | — |

**Categories:**
- Drainage: `catch_basin_clogged`, `street_flooding`, `highway_flooding`, `sewer_backup`, `manhole_overflow`, `catch_basin_damaged`, `catch_basin_other`, `culvert_blocked`, `basin_contamination`.
- Street: `pothole`, `cave_in`.
- `other`.

**Verification statuses** (from DEP resolution text; the full rules are in the data-source register):

| Status | Meaning |
|---|---|
| `agency_found_obstruction` | DEP found debris obstructing the basin, or a grease blockage in the sewer |
| `agency_found_defect` | DEP confirmed a defective sewer |
| `agency_cleaned` | DEP cleaned the basin |
| `agency_not_found` | DEP couldn't find the problem |
| `agency_functioning` | DEP found the basin working |
| `capacity_surcharge` | Sewer capacity was exceeded; this is **not** a blockage |
| `duplicate` | Already reported by someone else |
| `referred` | Passed to another agency |
| `pending` | Under investigation |
| `no_inspection` | DEP resolved it by phone; no field inspection |
| `none` | No resolution yet |
| `unknown` | Text Swale couldn't classify |
| `unverified` | Swale has no rules yet for this agency's resolutions, e.g. DOT potholes in M1. The raw text is still in `source_fields`. |

```ts
interface IncidentProps {
  layer: "incidents";
  knowledge_type: "reported";
  category: string;
  category_label: string;
  reported_at: string;
  closed_at: string | null;
  source_status: string;                 // the source's own status: "Closed", "Open", "In Progress", ...
  address: string | null;
  verification: {
    status: string;                      // see the table above
    knowledge_type: "observed" | "reported"; // "observed" only for DEP field findings
    basis: "dep_311_resolution" | null;
    rule: string | null;                 // e.g. "dep-res-obstruction-v1"
    text: string | null;                 // the raw DEP resolution text, unedited
    at: string | null;
  };
  linked_basin: { id: string; distance_ft: number; method: string; knowledge_type: "inferred" } | null;
}
```

### `GET /incidents/{id}`

Returns the same `Feature`, plus `properties.source_fields`: the original `agency`, `complaint_type`, `descriptor`, `descriptor_2`, and the other raw fields, unmodified. `geometry` may be `null` when the source has no coordinates.

## 5. Provisional endpoints (M2 and later; shapes may change)

```ts
// M2: observed flooding
// GET /sensors?bbox=          -> FeatureCollection<{ name; tidally_influenced: boolean; installed_at; removed_at|null; lowest_point_height_delta_in }>
// GET /flood-observations?bbox=&since=&until=
//                             -> FeatureCollection<{ sensor_id; started_at; ended_at; max_depth_in; duration_min; duration_above_4in_min; ... }>

// M2: DEP stormwater flood maps (predicted, external)
// GET /flood-maps?scenario=moderate_current|moderate_2050|extreme_2080|limited_current&bbox=
//                             -> FeatureCollection<{ scenario_code; depth_class; label }>

// M2: scenarios and runs
// POST /scenarios  body:
type ScenarioCreate =
  | { kind: "design_storm"; name: string; area_id: string; intensity_in_hr: 1.77 | 2.13 | 3.66 | number; duration_min: number }
  | { kind: "nws_forecast"; name: string; area_id: string; hours: number }
  | { kind: "custom"; name: string; area_id: string; hyetograph: { t_min: number; intensity_in_hr: number }[] };
// -> 201 Scenario { id; kind; hyetograph; total_depth_in; peak_in_hr; duration_min; assumptions: string[]; source_ref|null; content_hash; created_at }

// POST /simulation-runs  body: { scenario_id: string; runner?: "local" | "daytona"; params?: { blockage_factor?: number } }
// -> 202 { id; status: "queued"; links: { self; results; logs } }
interface SimulationRun {
  id: string;
  status: "queued" | "running" | "succeeded" | "failed" | "timed_out" | "cancelled";
  scenario_id: string;
  model_version: string;
  runner: "local" | "daytona";
  queued_at: string; started_at: string | null; finished_at: string | null;
  timeout_s: number;
  inp_sha256: string | null;
  error: { code: string; message: string } | null;
  summary: { basins_flooded: number; total_flood_volume_ft3: number } | null;
  assumptions: Record<string, { value: number | string; unit?: string; basis: string }>;
}
// GET /simulation-runs/{id}           -> SimulationRun. Poll every 2 s until the status is terminal.
// GET /simulation-runs/{id}/results?bbox= -> FeatureCollection, knowledge_type "predicted",
//      properties { run_id; scenario_id; scenario_label; generated_at; flood_volume_ft3; hours_flooded; risk_class }
//      409 run-not-finished if the run hasn't succeeded
// GET /simulation-runs/{id}/logs      -> text/plain

// M3: risk ranking (inferred)
// GET /risk-rankings?bbox=&run_id=&limit=  -> FeatureCollection ordered by rank, properties:
interface RiskProps {
  rank: number; score: number; tier: "high" | "medium" | "low";
  method_version: string; assessed_at: string; run_id: string | null;
  factors: { id: string; label: string; knowledge_type: string; value: number; unit: string | null;
             weight: number; contribution: number; evidence_ids: string[]; explanation: string }[];
  missing_factors: { id: string; reason: string }[];
  data_as_of: Record<string, string>;
  caveats: string[];
}
// GET /risk-rankings/methodology  -> { method_version; factors: [{ id; definition; weight; knowledge_type }]; tiers; caveats }
// POST /inspections  body: { basin_id; inspected_at; result: "clear"|"debris_found"|"cleaned"|"damaged"|"not_found"; notes? }
```

**Predicted layers.** Render every predicted layer with a legend item that shows the scenario label and the run's `finished_at` or `generated_at`. Don't present a predicted layer as current conditions.
