# Swale API v1: frontend contract

- **Status:** DRAFT. The backend proposes it; the frontend reviews it.
- **Stable:** the endpoints marked **M1** become stable once agreed.
- **Provisional:** endpoints marked M2 and later. Their shapes may still change.
- **Changes:** go through the changelog at the bottom.

## 1. Basics

- **Base URL (dev):** `http://localhost:8000/api/v1`. The OpenAPI document is at `/api/v1/openapi.json`, and interactive docs are at `/docs`.
- **Format:** JSON. Map layers are **GeoJSON (RFC 7946)**:
  - `FeatureCollection` for lists, `Feature` for single items.
  - Coordinates are WGS84, in **`[longitude, latitude]` order**.
  - There's no `crs` member.
- **IDs:** opaque, stable strings such as `catch_basin:CB305116` or `incident:nyc311_69804630`. Use them as feature IDs for hover and selection state. Don't parse them, and URL-encode them in paths.
- **Times:** ISO-8601 in UTC with a `Z` suffix, e.g. `2026-07-22T18:36:00Z`. Converting to New York time for display is the frontend's job.
- **Units:** every field name carries its unit: `_in` (inches), `_ft`, `_in_hr`, `_min`, `_cfs`, `_ft3`. A number without a unit suffix is a count or a score.
- **CORS:** the dev origins are set with `SWALE_CORS_ORIGINS` on the backend. Tell the backend your dev-server URL, e.g. `http://localhost:5173`.
- **Versioning:** within v1, changes are additive only (new endpoints, new optional fields). Ignore fields you don't recognize. Breaking changes ship as `/api/v2`.

## 2. Trust fields: render these differently

Every feature has `properties.knowledge_type`:

| Value | Means | Suggested styling |
|---|---|---|
| `observed` | Measured or confirmed: a sensor reading, the DEP inventory, or a DEP field finding. | Solid |
| `reported` | An unverified public report, i.e. a 311 complaint. **It isn't proof** that the problem exists or still exists. | Hollow or outlined |
| `predicted` | Model output (a Swale simulation, DEP flood maps, an NWS forecast). **It isn't current flooding.** | Translucent or hatched, **always labeled with the scenario name and run time** |
| `inferred` | Derived by Swale's own rules, such as a risk score or an incident-to-basin link. | Dashed, labeled "inferred" |

Every feature also has `properties.source`:

```ts
interface SourceRef {
  id: string;             // a key in the data-source register, e.g. "nyc311"
  dataset?: string;       // the publisher's dataset ID, e.g. "erm2-nwe9"
  record_id: string;      // the original ID at the source
  url: string;            // a link to the original record
  updated_at?: string | null; // the source's own update time, when it gives one
}
```

Each list response's `meta.sources[]` gives a per-source `stale` flag. When it's `true`, grey the layer out and show "as of <fetched_at>". `stale` is measured from when the rows were fetched from the source, not from when they were loaded, so a replayed snapshot shows as stale once it's old.

## 3. Shared conventions

**Query parameters**
- `bbox=minLon,minLat,maxLon,maxLat` is **required** on every map-layer list endpoint.
  - It must be four finite numbers with min < max on both axes, and it must intersect NYC (−74.27, 40.49, −73.68, 40.92). Otherwise the API returns 422.
  - Send the visible map extent, never the whole city.
- `limit` defaults to 1,000, with a maximum of 5,000.
- `cursor` is an opaque value taken from `meta.next_cursor`.
- If `meta.truncated` is `true`, there are more features. Either page through them or zoom in.

**List response envelope:** a GeoJSON `FeatureCollection` plus a `meta` foreign member. RFC 7946 allows foreign members, and map libraries ignore them.

```ts
interface LayerResponse<P> {
  type: "FeatureCollection";
  features: Feature<P>[];
  meta: {
    api_version: "1.0";
    layer: string;                       // e.g. "catch_basins"
    request_bbox: [number, number, number, number];
    filters: Record<string, unknown>;    // effective filters, defaults included
    count: number;                       // features in this page
    limit: number;
    truncated: boolean;
    next_cursor: string | null;
    generated_at: string;
    sources: SourceFreshness[];
  };
}

interface SourceFreshness {
  id: string;
  dataset_updated_at: string | null;
  last_ingested_at: string | null;
  fetched_at: string | null;   // when the rows were fetched from the source; `stale` is measured from this
  stale: boolean;
}

interface Feature<P> {
  type: "Feature";
  id: string;
  geometry: GeoJSON.Geometry | null;     // null only on detail endpoints, when the source has no coordinates
  properties: P & {
    layer: string;
    knowledge_type: "observed" | "reported" | "predicted" | "inferred";
    source: SourceRef;
    ingested_at: string;
  };
}
```

**Errors** use RFC 9457 problem details, with `Content-Type: application/problem+json`:

```json
{
  "type": "/api/v1/problems/invalid-bbox",
  "title": "Invalid bbox",
  "status": 422,
  "detail": "bbox must be minLon,minLat,maxLon,maxLat with min < max on both axes.",
  "instance": "/api/v1/catch-basins?bbox=-73.97962,40.66457,-74.01995,40.69255",
  "errors": [{ "param": "bbox", "code": "inverted_lon", "message": "minLon must be less than maxLon" }]
}
```

Problem types:

| Type | Status |
|---|---|
| `invalid-bbox`, `bbox-outside-coverage`, `invalid-parameter` | 422 |
| `not-found` | 404 |
| `run-not-finished` | 409 |
| `upstream-unavailable` | 503 |
| `internal` | 500 |

## 4. M1 endpoints (first to ship)

In the examples below, source fields come from real records. Swale-generated values (`ingested_at`, `last_ingested_at`, `generated_at`, `build`) show the format only.

```json

  "build": "<git sha>",
```

### `GET /incidents?bbox=…&category=…&verification=…&since=…&until=…&basin=…&limit=…&cursor=…`

**Filters**

| Parameter | Accepts | Default |
|---|---|---|
| `category` | A comma-separated list | All categories |
| `verification` | A comma-separated list of statuses | All statuses |
| `since` / `until` | Filters on `reported_at` | `since` = 365 days ago, echoed back in `meta.filters` |
| `basin` | A basin ID; returns incidents linked to that basin | — |

**Categories:**
- Drainage: `catch_basin_clogged`, `street_flooding`, `highway_flooding`, `sewer_backup`, `manhole_overflow`, `catch_basin_damaged`, `catch_basin_other`, `culvert_blocked`, `basin_contamination`.
- Street: `pothole`, `cave_in`.
- `other`.

**Verification statuses** (from DEP resolution text; the full rules are in the data-source register):

| Status | Meaning |
|---|---|
| `agency_found_obstruction` | DEP found debris obstructing the basin, or a grease blockage in the sewer |
| `agency_found_defect` | DEP confirmed a defective sewer |
| `agency_cleaned` | DEP cleaned the basin |
| `agency_not_found` | DEP couldn't find the problem |
| `agency_functioning` | DEP found the basin working |
| `capacity_surcharge` | Sewer capacity was exceeded; this is **not** a blockage |
| `duplicate` | Already reported by someone else |
| `referred` | Passed to another agency |
| `pending` | Under investigation |
| `no_inspection` | DEP resolved it by phone; no field inspection |
| `none` | No resolution yet |
| `unknown` | Text Swale couldn't classify |
| `unverified` | Swale has no rules yet for this agency's resolutions, e.g. DOT potholes in M1. The raw text is still in `source_fields`. |

```ts
interface IncidentProps {

  knowledge_type: "reported";
  category: string;
  category_label: string;
  reported_at: string;
  closed_at: string | null;

    status: string;                      // see the table above

    rule: string | null;                 // e.g. "dep-res-obstruction-v1"
```

`blockage_factor` (default 0.5) narrows the inlet of each basin where DEP's own resolution recorded an obstruction in the past year.   summary: { stations: number; delayed: number; alert: number; flooding_reported: number; trains_in_area: number; alerts: number };
```ts
  stations: { station_id: string; gtfs_stop_id: string; name: string; routes: string[]; lon: number; lat: number;
    status: "normal" | "alert" | "delayed" | "flooding_reported" | "no_service"; reasons: string[];
    trains_next_30_min: { predicted: number; scheduled: number | null };
    delay_min: { median: number | null; max: number | null; trains_matched: number };   // predicted minus scheduled arrival; negative = early
    next: { N: Arrival[]; S: Arrival[] }; direction_labels: { N: string; S: string }; alert_ids: string[] }[];
  trains: { route: string; trip_id: string; stop_id: string; direction: "N" | "S"; status: "incoming_at" | "stopped_at" | "in_transit_to";
            seen_at: string | null; knowledge_type: "observed" }[];
  alerts: { id: string; alert_type: string | null; header: string; description: string | null; routes: string[]; stops: string[];
            station_specific: boolean; mentions_flooding: boolean; active_from: string; updated_at: string | null;
            knowledge_type: "observed"; basis: "MTA service alert" }[] }
interface Arrival { route: string; direction: "N" | "S"; trip_id: string; predicted_at: string; minutes_away: number;
  scheduled_at: string | null; delay_min: number | null }
// GET /subway/history?area_id=BK0601&hours=6  -> { polls: { polled_at, delayed, flooding_reported, alerts, stations[] }[] }
```

Status rules: `delayed` when the median train is 5 min or more late, or fewer than 60% of scheduled trains are predicted in the next 30 min. `alert` when an MTA delay alert names a line serving the station (it may be elsewhere on the line). `flooding_reported` when an active MTA alert for the station or its lines mentions flooding or water conditions. MTA publishes no station flood sensors, so the API never claims a station is flooded on its own evidence.

## 6. Public selected-context assistant and briefings

This additive `public-context-v1` service is separate from `/briefings`, which
retains its crew-ranking contract. The frontend uses `/context/*` for public
selected-station/entrance/basin/incident explanations; it never substitutes crew
maintenance instructions. Implementation is not a live-provider acceptance claim.
See [CONTEXTUAL_MASCOT_BRIEFINGS.md](../CONTEXTUAL_MASCOT_BRIEFINGS.md) for lifecycle,
provider controls and verification boundaries.

### Requests and subject identity

`POST /context/agent` accepts the following JSON, with unknown fields rejected:

```ts
interface ContextAgentRequest {
  prompt: string; // 1–2,000 characters
  context: ContextRequest;
  language?: "en" | "es" | "zh" | "ar" | "ru" | "fr"; // default en
  use_model?: boolean; // default false; credential presence is insufficient
}
interface ContextRequest {
  kind: "station" | "entrance" | "basin" | "incident";
  id: string; // full opaque subject ID
  station_id?: string | null;
  water_view?: "normal" | "flood_simulation"; // default normal
  view_scope?: "overview" | "station_exploration"; // default overview
  state_version: string;
  snapshot?: {
    station_id: string;
    entrance_id?: string | null;
    scenario_id: string;
    model_version: "swale-entrance-storage-v1";
    elapsed_seconds: number; // 0–1,800, not beyond inputs.durationS
    fingerprint: string;
    inputs: {
      streetDepthM: number; // 0–2
      barrierHeightM: number; // 0–2
      inflowCapacityLps: number; // 0–100
      drainageCapacityLps: number; // 0–100
      durationS: number; // 1–1,800
    };
    results: Record<string, number>; // bounded finite fields, at most 20
  } | null;
}
```

`POST /context/briefings` accepts the same fields except `prompt` and uses the
default selected-subject explanation request; success is HTTP201. Agent success
is HTTP200. Station IDs are full `subway_station:<GTFS ID>`. Backend entrance IDs
are `subway_entrance:<key>`; local source-linked entrance catalog IDs are
`model_entrance:<source row ID>`. Basin and incident IDs retain their existing
tables. Subject existence and entrance/station relationships are validated
server-side; static-only model coverage is explicitly disclosed. An unsupported
subject is 404; a contradictory station/snapshot relationship is 422.

`snapshot` values are browser-supplied **unverified hypothetical** inputs/results,
not observations, server-verified calculations or backend simulation runs. No
`run_id`, arbitrary coordinate/URL, scientific coupling or present-water claim is
accepted. Normal hides hypothetical water; it does not establish dry/safe/open
conditions. Fixed source time, retrieval time, monitoring time, scenario time and
briefing creation time remain different clocks.

### Response and commands

```ts
interface ContextBriefing {
  id: string; // 32 lowercase hexadecimal characters, process-local record
  context_key: string; // SHA256 of canonical request plus server evidence
  context: ContextRequest; // normalized echo; absent optionals can be null
  subject: { id: string; station_id: string | null; geometry: GeoJSON.Geometry };
  transcript: string; // complete validated content plus full localized warning
  original_transcript: string; // complete English transcript
  language: "en" | "es" | "zh" | "ar" | "ru" | "fr";
  source: "model" | "template" | "machine_translation";
  model: string | null;
  evidence: {
    id: string; subject_id: string;
    type: "STATIC INVENTORY" | "HISTORICAL" | "OBSERVED" | "SCENARIO";
    source_id: string; url: string | null;
    source_time: string | null; fetched_at: string | null;
    stale: boolean | null; text: string;
  }[];
  actions: ContextAction[]; // at most 4
  limitations: string[];
  created_at: string; expires_at: string;
  error: string | null;
  translation: { configured: string[]; available: string[]; verified: false };
  audio: { ready: boolean; url: string | null };
  content_version: "public-context-v1";
}
type ContextAction =
  | { type: "set_view"; view_scope: "overview" | "station_exploration" }
  | { type: "set_water_view"; water_view: "normal" | "flood_simulation" }
  | { type: "seek_simulation"; elapsed_seconds: number }
  | { type: "select_station"; station_id: string }
  | { type: "set_layers"; layers: { basins?: boolean; complaints?: boolean; floodZones?: boolean; buildings?: boolean } }
  | { type: "highlight"; ids: string[] }
  | { type: "fly_to"; target_id: string }
  | { type: "play_briefing" }
  | { type: "stop_audio" };
```

English `source:"model"` means a real bounded model selected IDs from the server's
evidence sentences and returned guarded UI actions. The server creates factual
prose from those sentences; arbitrary model prose is not executed or presented as
new evidence. Disabled/failed/rejected generation returns the deterministic public
template and explicit `error`, with no model actions. This is a graceful fallback,
not proof of model operation. Unknown commands/arguments fail closed.

Source text never authorizes actions. Server intent/identity checks and frontend
state-version, loaded-ID, view and scenario checks all apply. A related navigation
series is prevalidated as a batch before UI mutation. Seek requires the existing
selected snapshot and explicit requested time within its duration. Station switch
targets must be explicitly requested. Highlight is bounded to at most20 validated
IDs; the UI may enforce narrower active-view limits. Playback requires explicit
user intent and a matching current transcript; there are no administrative or
real-world write tools.

### Translation, retrieval and audio

| Endpoint | Body / response |
| --- | --- |
| `GET /context/capabilities` | Provider opt-ins/remaining calls, configured and conditionally available languages, conservative persistent budget reservations, token counters and cache limits. No provider generation. |
| `GET /context/briefings/{id}` | Existing `ContextBriefing`; expired/missing is404. |
| `POST /context/briefings/{id}/translations` | `{language, use_model:false}` by default; non-English requires explicit model opt-in. HTTP201 returns a **new** language-specific ID with the same `context_key` and empty actions. |
| `POST /context/briefings/{id}/audio` | Exactly `{user_intent:true}`; HTTP200 returns the prepared record. Missing/false intent is422; disabled/exhausted speech is409. |
| `GET /context/briefings/{id}/audio` | Prepared `audio/mpeg`, `Cache-Control: private, no-store`; missing/unprepared is404. |

IDs in these paths match `^[0-9a-f]{32}$`; contextual endpoints accept no query
parameters. The frontend proxy and bounded release ASGI guard expose exactly these
methods without enabling unrelated legacy/admin POST routes. The release guard
also bounds POST bodies to128KiB and body receipt to10 seconds.

Machine translations retain original English and the full language-specific
warning. Sentence count/order, numeric sequences, source IDs/names/routes,
recognized physical units and conservative negation/uncertainty qualifiers are
checked. These lexical checks do not prove semantic fidelity; human review is not
claimed, and `verified` remains false. Configured language, current provider
availability, live-tested translation, voice inventory and actual audible output
are separate statuses. No English text is silently relabelled as translated.

Complete transcripts exceeding4,000 characters are rejected, not truncated. The
existing ElevenLabs multilingual provider uses a fixed backend voice; it has no
automatic alternate voice or paid retry. Optional browser speech dynamically
discovers voices, labels local versus remote services, offers only matching
transcript languages and segments the complete text. Voice selection alone never
translates. Play/Replay or an explicit typed play request initiates one playback
owner; selection/translation completion never autoplay. Cancellation and context
generation checks reject obsolete narration.

Records/audio are process-local and bounded:64 records,1,800-second TTL,2MiB per
provider audio and16MiB aggregate audio cache. Restart loses transcripts/audio;
the private provider reservation ledger persists. Contextual operations require no
DB migration, ingestion or DB write. Paid providers default disabled/zero allowance
and require server opt-in, approved credentials, attempt caps and the persistent
private ledger. The finalization launcher caps allowance at US$1, three model
attempts and one audio attempt; conservative reservations occur **before** network
and failed/uncertain attempts consume them. A non-English model create can require
two model attempts (selection plus translation). Capability HTTP200 or an audio
URL does not establish model, audible-output or full backend-readiness acceptance.
